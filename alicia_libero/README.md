# Alicia-D × LIBERO 桌面操作仿真台（PySide6）

用 **Alicia_D_v5_6_gripper_50mm** 机械臂在 MuJoCo 里做桌面操作任务：
界面用 **PySide6**，任务素材来自 ``Datasets/libero_assets``（LIBERO 官方素材，402 MB / 60 个物体），
操作方式支持 **鼠标拖拽（IK 跟随）**、**键盘虚拟示教臂**、**关节滑块**。

> ⚠ **动作规划已重写为「闭环技能库」**（`skills.py`）：旧版"规划时算死绝对高度"的实现已整体删除
> （留档见 §9），现在是每帧读接触/位置决定下一步的**闭环技能**，含判分后的**回程**（§8.8）
> 与抓取物的**随机安放**（§8.9）。界面上「▶ 自动完成本关 / 单步 / 明细」就是这个库的驱动器；
> 手动操作（鼠标拖拽 / 键盘 / 滑块）会自动暂停它。

## 2. 素材分析结论（回答"能构建几个任务"）

`libero_catalog.py` 把 ``libero_assets`` 全部扫了一遍，得到 **60 个可用物体**（另外的场景/贴图不计）：

| 分组 | 数量 | 代表物体 |
| --- | --- | --- |
| 餐具/容器 | 10 | plate（138×138×19）、akita_black_bowl（107mm）、篮子和木托盘、平底锅 |
| 食品瓶罐 | 14 | ketchup（56×37×146）、new_salad_dressing、popcorn、butter、chocolate_pudding |
| 日用杂项 | 17 | porcelain_mug、wine_bottle、black_book、wooden_tray、desk_caddy |
| 可动家具 | 17 | microwave 门/抽屉等（本工程未用于任务，可动部件需另外建模） |
| 场景道具 | 2 | desk、living_room_table |

分析器对每个物体做四件事（都能在 UI 里看到）：

1. **碰撞几何**：直接沿用 LIBERO 预烘焙的**凸盒分解**（`<name>.xml` 里的 `type=box`），
   解析后得到物体自身坐标系下的 AABB → 用于精确摆放到桌面、判分
2. **视觉网格**：XML 指向的 `visual/*_vis.msh` 在本仓库里**并不存在**，按规则回退到同目录的 `.obj`
   （MuJoCo 不读 OBJ 的贴图，所以用 catalog 里的纯色材质代替）
3. **俯视抓取高度**：把物体沿 Z 切成 24 层，每层取所有相交碰撞盒的**联合水平轮廓**，
   轮廓较窄的那条边就是夹爪要张开的宽度 → 给出「最窄一层」的高度区间 + 该层的夹取宽度
4. **可夹判断**：50mm 夹爪的实际开口约 **45mm**，据此判断哪些物体能夹。
   实测 **36/60** 可夹；盘子（138mm）、碗（81~107mm）、马克杯（125mm）、篮子（170mm）
   这类"宽口"物体只能当**目标容器**，不能当抓取物

**实测物理规律（本工程最关键的三条，都写进了代码注释）**

| 规律 | 结论 | 依据 |
| --- | --- | --- |
| 夹爪闭合方向 | **必须沿物体的窄边闭合** | 番茄酱 56×37mm，若沿 56mm 侧闭合，50mm 开口夹不上，搬运途中掉落（掉到桌下 533mm 外） |
| 夹取高度 | **TCP（tool0_site）= 物体原点 + 窄带中点** | 物理扫描：番茄酱可用区间为「原点 +30~+60mm」，窄带中点 +40mm 正在区间中间 |
| 释放高度 | **TCP = 目标面 + 物体底面偏移 + 夹取偏移** | 深放会撞容器、浅放会挂在篮沿上，公式算出后 t1/t3/t4 的落点误差 <30mm |

每个任务的判据都是**可量化**的（`libero_tasks.py` 里 `success` 字段）：

```python
{"xy": [0.22, 0.10], "xy_tol": 0.055,      # 抓取物 AABB 中心与目标的水平容差
 "z_ref": "table" | "target_top",           # 高度基准：桌面 / 目标物顶面
```

## 4. 界面使用

左侧面板从上到下：

1. **任务下拉框**：切换任务 = 重新生成并加载 MuJoCo 场景（9 个任务）
   - 任务描述、操作提示、**素材分析摘要**（抓取物尺寸/最窄处/50mm 夹爪能否夹）
   - 实时判据（黄字）与完成状态（绿字）
2. **操作方式**：鼠标拖拽（IK 跟随）/ 键盘虚拟示教臂 / 关节滑块
   - 关节滑块（J1~J6）在"滑块模式"下可直接拖动；其他模式下作为实时回显
   - 夹爪滑块：0 = 闭合，100 = 张开
   - ~~辅助按钮 ① 对准夹取位 / ② 夹取 / ③ 对准放置位 / ④ 松开~~ —— 已随动作规划删除
3. **视图/场景**：相机切换（斜前方 / 正上方 / 侧前方 / 腕部相机）、重新开始（复位场景）

鼠标 / 键盘：

| 操作 | 作用 |
| --- | --- |
| 鼠标左键拖动 | 移动夹爪目标点（IK 实时求解，按当前视角的屏幕方向换算成世界位移） |
| 滚轮 | 升降夹爪（±12mm/格） |
| Shift + 滚轮 | 夹爪开合 |
| `1`..`6` | 选择要微调的关节 |
| `,` / `.`（或 ←/→） | 选中关节 ∓2° |
| `O` / `C` | 夹爪张开 / 闭合 |
| `R` | 复位场景（物体回到初始位姿） |
| `T` | 切换相机 |

推荐的操作流程（以任务 1 为例）：

```
选中任务 → 鼠标拖动（或滚轮 / 关节滑块 / 键盘微调）把夹爪挪到物体旁并夹住
        → 拖到目标上方 → 张开夹爪放下 → 看左上判据变绿「任务完成」
```

## 5. 技术实现要点

**场景拼装**（`libero_scene.py`）：以 `Alicia_D_v5_6_gripper_50mm_teleop.xml`（位置伺服版）为骨架，
用 ElementTree 把地面、LIBERO 标准桌面、物体、相机、灯光插进它的 worldbody，
保留原有的 actuator 与 contact 排除；手臂的 `meshdir` 改成绝对路径，物体网格用相对该 `meshdir` 的
相对路径引用 —— 这样生成的场景 XML 放到任何目录都能加载。

**为什么必须先跑 `make_follower_xml.py`**：Robot-Descriptions 里的原始 MJCF
（`gripper_50mm.xml`）**没有任何 actuator**（nu=0），无法下发指令；
位置伺服版才能直接往 `data.ctrl` 写目标关节角。

**IK**（`alicia_ik.py`）：
* 从模型零位姿态反推「接近轴 / 夹紧轴在 tool 帧下的方向」（不能想当然认为某个轴就是接近轴，
  实测 tool 帧 Y 才是夹紧轴、Z 是接近轴）
* **两阶段求解**：先纯位置收敛（位置优先），再在**位置雅可比的零空间**里调整姿态
  —— 这样姿态能改、位置严格不掉（桌面网格可达率 93%，位置误差 ~0.0mm）
* 多种子重试：从"上一帧解"做种子会陷局部极小（实测差 46mm），失败时用零位种子重试
* 姿态约束是**软**的：强行要求"严格竖直向下"会把 J5 顶到 ±90° 限位，远处目标直接解不出来

**渲染**：`mujoco.Renderer` 离屏渲染 → `QImage` → `QLabel`（不另开 MuJoCo 窗口），
主循环 `QTimer(16ms)` 驱动：IK/控制 → `mj_step`×8（dt=2ms，≈1 帧 1/60s）→ 渲染 → 判分。

## 7. 踩坑记录（都已在代码里注释）

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| LIBERO 物体 XML 的 `quat` **未归一化** | 如 butter 写成 `0.0053 0 0.0053 0`（模长 0.0075），旋转矩阵退化、AABB 算成 0 | 解析与写场景时统一归一化 |
| 物体 XML 指向的 `visual/*_vis.msh` 缺失 | MuJoCo 报找不到文件 | 回退到同目录 `.obj`（按 `_vis.msh → .obj` 规则）|
| 夹爪"张开度"映射反了 | `opening=1` 实际把手指推到 0.025（**闭合**）→ 想夹紧却全张开，抓取全失败 | `finger_targets()` 改成 `(1-opening)*travel` |
| 夹爪闭合方向没对齐窄边 | 番茄酱搬到一半掉落，飞到桌下 | 按 catalog 的 AABB 较短边自动选闭合方向（yaw 0 或 90°）|
| 判据 z 下界太严 | 物体静止时底面 -0.4mm 被判失败 | 判据留 2mm 弹性 |
| **相机 `xyaxes` 手写错方向** | 界面里**只看得到地板**：`cam_front` 的 -Z 轴正好背对桌子、`cam_wrist` 朝天 | 改用 `look_at_xyaxes(位置, 看向点)` 自动计算；再加**分割渲染可见性测试**兜底 |
| `mujoco 3.13` 的 viewer 没有 `ctx` | 官方示例的 `mjr_overlay(viewer.ctx)` 直接 AttributeError | 改用 `Handle.set_texts()`（旧版走 mjr_overlay 分支）|
| `"" in "123456"` 恒为真 | 空文本按键走进数字分支，`int("")` 崩 | 先判 `if text and text in ...`，并从 keycode 兜底取字符 |
| 换任务后滑块与仿真不同步 | 滑块显示 0 而仿真以为全张开，按 C 无反应 | 加 `_sync_controls()` 同步控件与 session |
| **随机摆位不是"随便摆"** | t1 的瓶子摆到离底座 277mm 的角点时，手指把瓶子碰倒（实时宽度 37→122mm、4 档高度全夹空） | 先跑网格扫描（`_tools\diag_t1_grid.py`）量出失败点，再用区域避开（§8.9） |
| **夹持深度受"低位伺服漂移"限制** | t1 想夹得深一点时，远端（0.4~0.5m）"开口−物体宽"从 +1.3mm 恶化到 +11.9mm，手指蹭到瓶身、甚至把瓶子顶歪 | 取"两个极端摆位都不失手"的最深档（§8.10），并逐档量出"合爪质量"再定档位 |
| **随机目标物要连判据一起改** | 篮子也随机后，"画死的目标圆盘"和判分写死的 `success.xy` 都还停在标称位置（0.22/0.10）—— 会误导操作者、判分也和实际篮子对不上 | 目标被随机化时用 `xy_ref="target"` 取**目标物当前实际中心**判分，并且不再画固定圆盘（§8.9） |
| **斜放物体的 AABB 底面是空角点** | 平放进篮子的瓶子：AABB 底面 806mm（只比桌面高 6mm，差点被判失败），真实最低点其实 821mm 正压在篮底 | 判分高度改用**碰撞盒角点的最低点**（`check_success` → `object_lowest_z`）；轴对齐时不改变任何结果 |
| **细长物体不会自己倒进容器** | 平放的瓶子（145.6mm）比篮子内腔（122×111mm）长：长轴与篮子边平行时正中心松手 6/6 卡在沿口；朝向必须落在斜对角族（θ≈45/140/215/320 时 8~9/9） | 平放**随机朝向 + 生成前适配**到斜对角族（`SPAWN_LYING_YAWS`）；放置改成"篮口上方 15mm 凌空松手"（实测 15mm 最好、抬高更差）；实测平放 41/48（§8.9） |
| **薄物件的闭合轴要准到几度** | 平放的黄油能夹的只有 39.5mm 那对侧面、爪口 50mm：`calibrated_yaw` 的候选相隔 90°、残余 31.5° 时投影宽 39.5·cos31.5+76.2·sin31.5 = **72mm**，手指从两侧滑过、合爪到 0mm（夹空，物体纹丝不动） | 按实测**筛朝向**：8 个朝向里只有 θ∈{0,135,180,315}（yaw≈−90°/−135°）IK 咬得住 → `lying_yaws` 只留这 4 个；试过的"带符号闭环微调"因 IK 偏航误差换分支而失败，已放弃（§8.9.1） |
| **薄物件的"浅握"校验不出来** | 指面全在 TCP **之上** ~73mm，而黄油只有 17~40mm 厚：dz=+20 时指面整段停在黄油顶面之上、只咬住**顶角**——抬起 25mm 的跟随校验照样通过，但**长距离搬运途中会滑落**（判分水平偏 292~326mm、黄油躺在桌面上，而每一步都报 ✓，很难从失败信息看出来） | t2 单独把抓取档位改成 `dz=0` 打头（`GRASP_BAND_LADDER_TASKS`），指面盖住黄油 32mm；同时把黄油/盘子区域往内收，避免 ~300mm 的极端长距离搬运 |
| **旋转矩阵取"行"还是取"列"** | 想把"局部轴 i 在世界系的方向"拿出来写成 `rot @ np.eye(3)` 再取 `axes[i]` —— 取到的是矩阵的**行**（= 世界轴在局部系里的像，转置了），于是"哪条轴水平"判反，平放的黄油整局夹空（开口 50→1mm、黄油没动） | 用 `axes = rot.T`，`axes[i]` 才是第 i 列 = 局部轴 i 的世界方向；探针里把三条轴竖直分量打出来、对照 AABB 高度即可当场发现 |
| **躺姿的夹取点比立姿低 90mm** | 平放的瓶子要 TCP 压到 810~830mm，而机械臂离底座 ≥400mm 时压不到 870mm 以下（xy 漂 5~20mm、手指偏进瓶身） | 给"平放"单独收紧位置（`pose_regions`：x ≤ 0.08，离底座 291~400mm）；立姿仍用整个区域（§8.9） |
| **复位后算朝向要用刷新过的姿态** | `mj_resetData` 之后 `data.xquat` 还是旧值/全零，"立着"会被误判成"平放" → 闭合轴从 +90° 变成 −90°（GUI 冒烟抓到） | `reset()` 里 `_apply_spawn()` 之后先 `mj_forward` 再算 `grasp_yaw`（`_grasp_yaw` 里的 `is_upright` 依赖它） |

## 8. 动作规划：已重写为「闭环技能库」（`skills.py`）

上一版是"规划时算死绝对高度、执行时按帧数走"（留档见 §9），失败根因几乎都是
**用算出来的高度去决定"什么时候松手/夹住"**。现在换成 **闭环技能**：每帧读实际状态
（物体实时位姿、真实接触、夹爪开口与力），由判据决定下一步。

### 8.1 四个判据（全部实测，不再"算"）

| 判据 | 怎么测 | 用在哪 |
| --- | --- | --- |
| 夹住了吗 | 合爪后的**开口**要落在物体实时宽度附近 **且** 抬 25mm 时物体跟着走 | 抓取 |
| 到位了吗 | **被夹物**与目标物/桌面的**真实接触**（不再推算"内底/盘面"） | 放置 / 叠放 / 放到桌面 |
| 抬多高才安全 | `scene_rim_z()`：**现场实测**所有物体（含**出发**容器）的最高点 + 30mm | 搬运 |
| 推到位了吗 | 推滑专用：`gap_along()`（碰撞盒角点的**真间隙**）到目标前沿 ≤ 3mm 就撤力，再判 `check_success` | t6 推书 |

### 8.2 基本技能（都是生成器，每帧 `yield` 一次，由主循环推进 → 天然支持暂停/单步）

`ramp` 闭环限速移动 · `align_xy` 闭环 xy 对准（消除位置伺服 6~7mm 静态误差）·
`close_gripper` 合爪到"力/开口停滞" · `grasp_object` 抓取（4 档高度阶梯、逐档验证）·
`place_object` 放置（接触即停）· `push_object` 推滑（t6，配 `world_box_corners` / `gap_along`
算真间隙）· `release_object` 松手并验证 · `return_home` **回程**（判分后把臂收回零位，见 §8.8）

界面上的「▶ 自动完成本关 / 单步 / 状态 / 明细」就是这个库的驱动器；手动操作会自动暂停它。

### 8.4 黄油那关是怎么修好的：夹爪方向必须**实测**，不能按约定推

命令偏航角与**真实闭合轴**不是简单对应关系 —— `AliciaIK` 对姿态是**软约束**

薄边沿 Y）：

| 命令 yaw | 实测闭合轴（两指 body 连线） | 与薄边夹角 | 结果 |
| --- | --- | --- | --- |
| **+90°**（原约定的答案） | (0.94, 0.15, 0.30) | **81°** | 手指"横着"扎进 76mm 长的瓶身侧面 → 撞几次也夹不住 |
| **-90°** | (0.11, 0.99, -0.12) | **9.5°** | ✅ 夹住 17mm 薄边，开口 18mm / 物体宽 17mm |

现在 t2 走 `skills.calibrated_yaw()`：把末端摆到物体上方，对候选角**逐个实测**两指连线、

**其它任务的代码路径与帧数一字未变**（当时改前改后 395/326/348/306/310 完全一致；

### 8.5 布丁那关是怎么修好的（t3）：两个叠加的根因，都不是"爪口够宽"能解决的

用户看到"夹爪下去把物品撞歪了"是真的。实测（`skills.py` 里的注释有完整数据）：

**根因 ①：开口判据的参照物被自己的手指污染。** 判据"开口要和物体宽度对得上"用的是
**实时 AABB 宽度**，而布丁盒只有 27.4mm 宽，指尖一压就歪，实测闭合那一刻的实时宽度依次是
**65.7 / 56.0 / 52.9mm** —— 于是把三次真夹住（物体底跟随 +19.8 / +17.5 / +16.8mm）全判成
失败、主动在空中松爪，盒子摔回桌面越摔越歪。改用 catalog 里**建场景时量好的** `grasp_width`
（27.4mm，与三次实测开口 26.4/31.9/32.1 都吻合、与空夹的 −0.2mm 差 27mm）。

**根因 ②：矩形截面斜着量就是 51mm 宽，爪口 50mm 根本套不下去。**
"爪口 50mm > 盒宽 27.4mm"是**错的比法**：沿闭合轴的投影宽 = 27.4·cosθ + 46.3·sinθ。
IK 把姿态当**软约束**（位置优先 + 零空间修正），命令 yaw=0° 时实测真实闭合轴与盒子窄边
差 **θ=40°** → 投影 **51.4mm ≈ 爪口**（间隙为负）。旧代码要等"连续 14 帧不动"才停，
而这 14 帧里命令点还在以 3.5mm/帧 往下走（**≈49mm 过行程**）→ 等于用伺服力把盒子
**拧了 25°**（按高度切片对比：沿闭合轴投影 51.4→39.9mm、垂直轴投影 52.7→52.0mm）。

修法（`CONTACT_STOP_TASKS = {"t3_pudding_into_ramekin"}`，其它任务不动）：

1. **手指一碰到物体就停**（≤1 帧、≤1.75mm 过行程），就地合爪 → 不再有 49mm 的推挤；
   触到后**跳过**低位横向微调（任何横move 都是侧推）；
2. 先扫 0°/90°/180° 三个朝向（`plan_clear_yaw`，顺便就把末端摆到对齐高度），
   用两指 body 连线量每个朝向的**真实**闭合轴与预计单边间隙（写进界面明细）；
3. 高度档把 `dz=0` 提到第一档（实测只有这一档能夹到盒子**窄边**，`dz=+20mm` 只会卡在盒顶、
   开口停在全开 51mm = 空夹）。

实测效果：物体朝向 **+0.0° → +0.2°**（修前被拧 25°）、AABB 27.4×46.3 → **28.1×47.3mm**、
开口 **27.6mm ≈ 窄边 27.4mm**、判分水平偏差 **5mm**（修前 14mm）、抓取段 601 → **238 帧**。

### 8.6 推书那关（t6）：从"把书推上盘子"改成"推到盘沿前、盘子不许动"

这一关前后修了两轮，第二轮是**判据本身不成立**：

**第一轮：你看到的"没推动"是真的。** 逐帧实测（`push_object`，只有 t6 用这个技能）：

| 阶段 | 帧 | 书心移动 | 指尖接触 |
| --- | --- | --- | --- |
| 抬臂准备 | 8 | 0.0mm | 无 |
| **绕到书后方**（旧） | 420 | **20.7mm** ✗ | **有** ✗ |

根因：旧版是**一步** `goto(back)` 直接到"书后方 804mm"，等于**贴着桌面横穿**过去 ——
路上先把书撞了 20.7mm，指尖一路贴着书，推的时候很容易被"卡住"判据（连续 60 帧不动）
提前收场。改成**高处绕行 → 竖直降到书后方**后：路上书心移动 **0.0mm、零接触**
（见 `skills.py` 踩坑 7）。

**第二轮：判据要求书"爬上盘子"，物理上做不到。** 实测数据（脚本
`E:\deepenv\_tools\diag_t6d.py`，扫「盘子质量 × 推速 × 停手间隙」）：

* 书 134×110×28.7mm、**投影半宽就有 84mm**，而旧判据是"书心进盘心 85mm 内" ——
  等于要求书**爬到盘子上**；可盘子高 19mm，且它的碰撞体是 **10 个台阶式方块（没有斜坡）**，
  书根本骑不上去；
* 机械臂的推力又远大于盘子摩擦：把盘子加重到 **920g**、只要继续顶，盘子照样被推走 100mm；
  而 libero 素材默认 `density=100`（≈泡沫），**盘子只有 11.5g**，书轻轻一碰就飞 ——
  这就是你实测到的"盘子被书推走"。

修法（**都只作用在 t6**）：

1. `libero_tasks.py`：t6 的盘子覆盖 `density: 2400`（≈瓷盘 276g；t2/t4 的盘子不受影响，
   机制沿用 t5 托盘那一套）；判据从"书心进盘心 85mm"改成**"推到盘沿前"**——
   判据点取实测停手位置 `(117,-14)mm`，容差 40mm（起点距它 120mm，不会白送）；
2. `skills.py`：新增 `world_box_corners()`（物体每个碰撞盒的世界系角点）与
   `gap_along()`（沿推进方向量**真间隙**，支持函数）。**为什么不能用 AABB**：书推进时
   会转，AABB 从 134×110mm 涨到 172×164mm，用 AABB 投影估间隙会低估 20mm 以上
   （"以为还差 3mm，其实已经顶上盘子了"）；
3. 推滑主循环改成：朝**目标物体当前中心**逐帧重新对准 → 间隙 ≤ 3mm 就**撤力收手**
   （目标回退 3mm）→ 等稳定 → 判分；全程守着"目标物体位移 > 12mm 直接报失败"。

实测效果（`E:\deepenv\_tools\diag_t6.py`）：

| 指标 | 修前 | 修后 |
| --- | --- | --- |
| **盘子全程最大位移** | **99~122mm** ✗ | **0.0mm** ✓ |
| 书心最终位置（判据点 (117,-14)） | 偏差 83mm（擦线） | **1.9mm** |
| 书心累计移动 / 帧数 | 244mm / 934 | 121mm / **689** |

四种停手间隙（0/2/5/10mm）× 三种盘重（11.5/69/276g）实测**盘子位移全是 0.0mm**；
±10mm 起始抖动 ×5 = **5/5 通过**；其余 8 关帧数一字未变。

### 8.7 叠放那关是怎么修好的（t7）：**夹爪抓的是"对角线"**，布丁在爪子里能转

现象（用户报的"放不到罐顶"）：布丁最后落在罐**旁边**的桌面上，判分偏 84mm、低于罐口 76mm。
逐帧量"倾斜量"（AABB 的 z 向高度，静置 80.2mm，只有倾斜才会变高）才看出真相：

| 阶段（旧的第 3 次夹取） | AABB 高度 | TCP z | 说明 |
| --- | --- | --- | --- |
| 对齐 / 竖直下降 | 80.2mm ✓ | 913→867 | 还没碰它，是直的 |
| 合夹爪 | 80.2→81.9 | 865→**859** | 开口停在 **35mm**（物体宽 45mm）= 松的 ✗ |
| 抬起验证 / 抬到安全高度 | 83.2→**87.3** ✗ | 859→960 | 布丁开始歪 |
| 移到目标上方 | 87.3→**95.2** ✗ | 960→968 | 歪 ~35° |
| 下降放置 | 95.3 ✗ | 965→936 | **只有一个角**点在罐顶（接触点 z=873.6，法向竖直） |
| 等待稳定 | 95.8 → **27.4** | | 角点支不住 → 滑落，侧倒在罐旁边的桌上 ✗ |

根因：布丁盒 27.4×46.3×80.2mm **又高又轻**，而**实际闭合轴≠命令 yaw**（`AliciaIK` 把姿态当软约束）。
实测不标定时闭合轴是 **135.7°/115.5°/128.9°**，沿闭合轴的投影宽
= 27.4·cosθ + 46.3·sinθ 涨到 **70~81mm**，比爪口 50mm 还宽 —— 手指其实是**夹着布丁的对角线**
（两个角点接触），布丁在爪子里能自由旋转，一抬起来就歪；高夹点（TCP 859mm，比 catalog
建议的 814mm 高 45mm）又放大了力臂。

修法**只有一处**：把 t7 也加进 `YAW_CALIBRATED_TASKS`（与 t2 同一套实测标定机制）——
在物体上方对候选偏航角逐个摆好、用两指 body 连线量真实闭合轴，挑与薄边最平行者：

| 配置 | 闭合轴 / 投影宽 | 抬起阶段最大倾斜 | 判分 |
| --- | --- | --- | --- |
| 不标定（现状） | 135.7°/115.5°/128.9° → **70~81mm** ✗ | +7.9mm ✗ | ❌ 偏 77mm / 低 76mm |
| **标定** | **−0.0° / 27.4mm** ✓ | **+0.3mm** ✓ | ✅ 偏 **9mm** / 高度 **−1mm** |

实测效果：抓取"开口 27mm（物体宽 27mm）、抬起跟随 20mm"，结束时 AABB 高度 **81.1mm**
（= 直立，修前 27.4mm 是躺着），帧数 635 → **519**；±10mm 抖动 ×5 = **5/5 通过**。

> 经验：这是 t2/t3 那条教训的第三次复现 —— **"命令的偏航角"和"真实的闭合轴"不是一回事**，
> 只要物体的薄边接近爪口（或又高又轻怕转），就必须**实测**闭合轴，不能按约定推。

### 8.8 任务结束后的**回程**（`return_home`）：把臂交还给零位

用户报的："每个任务算通过了，但任务做完机械臂没有回程" —— 判分一结束，整条臂就停在刚摆好的
物体上方几十毫米处（`place_object` 的"放稳"那一步），既挡相机视野，也没法直接接着跑下一关。
现在 `script_for` 在**判分之后**追加一步 `回程`：

```
张开夹爪 → 回程：抬到安全高度 → 回程：横移到零位上方 → 回程：落到零位 → 等伺服收稳
```

三层判断都来自实测（脚本 `E:\deepenv\_tools\diag_home.py` / `diag_home_xy.py`）：

| 问题 | 实测 | 做法 |
| --- | --- | --- |
| 零位在哪 | `reset()` 后 TCP = **(42.8, 0.4, 908.2)mm**（6 关节目标全 0） | `SimSession.reset()` 记进 `sess.home_tcp`，回程终点用它 |
| 能不能直接横move | 结束时末端下方就是物体 | 先**原地竖直**抬到"当前场景全部物体最高点 + 60mm"（与开局 `抬臂准备` 同一判据）再横移 |
| 能不能走关节空间收敛到零位 | ✗ t5 的 TCP 会下沉到 **880.9mm 并刮到木托盘**，t7 刮到布丁盒/番茄酱罐（关节空间直线在笛卡尔空间是弧，指尖会摆出去） | 全程走**笛卡尔 + IK**（`ramp`），单帧关节变化仍由 `set_ee_target` 的 8° 限速兜住 |
| 落到零位高度会不会压到东西 | 各关物体到零位 xy 最近也有 **91mm**（t9 木托盘），指尖总宽约 50mm | 保留"指尖一碰到外部物体就停"的兜底（`bumped`） |

结果：9 关回程全部**回到零位点，TCP 差 1~2mm**（`TCP [42 0 908]mm`），用了 **79~117 帧**
（≈1.3~1.9s）；任务本体帧数**一字未变**（395/497/467/326/348/689/519/306/310）。

**一个如实的代价**：回到的是零位**点**，不是零位**姿态** —— 工具接近轴与零位差
**24°（t1）/ 45°（t7）**（脚本 `diag_home_pose2.py` 实测）。原因是零位姿态的工具斜向上 45°，
而 IK 只会按 `down_orientation`（"接近轴竖直向下"）出姿态，全任务都这么用；要一模一样
只能走关节空间，而那条路实测会刮到物体（见上表）。所以"回程"的语义是
**回到零位点上方的待命姿态**，而不是逐帧复现 `reset()` 的位姿。

一个实现细节：`回程` 是**判分之后**追加的 `Step`，而"这关过没过"只看 `判分` 那一步
（`skills.task_ok()`）—— 这样回程失败/被兜底打断也不会把已经通过的任务判成失败。

### 8.9 任务多样化：抓取物**和目标物**随机安放，抓取物还能换**姿态**（已做 t1、t2）

用户的三次要求（t1）：①"瓶子应该在机械臂工作范围内随机安放（立着），而不是每次都固定一个位置"；
②"**篮子的位置也可以是随机的**"；③"瓶子的随机加上**姿态**随机：立着或者平放着"；
④"瓶子躺着的时候朝向也可以随机，不要固定 45° 角，加之前可以调整角度适配"。
随后要求**照 t1 的做法同样处理 t2**："黄油对应瓶子、盘子对应篮子，同样是黄油盒子随机位置和姿态，
盘子随机位置"。**除了 t1/t2，其余 7 关不写 `spawn_region`，代码路径都不进，帧数逐字不变。**

**怎么配**（`libero_tasks.py` 里 t1 的 `spawn_region`，其它任务不写这个键就完全不受影响）：

```python
"spawn_region": {
    "ketchup": {"x": [0.00, 0.18], "y": [-0.24, -0.10],
                "poses": ["upright", "lying"],                     # 立着 / 平放各 50%
                "pose_regions": {"lying": {"x": [0.00, 0.08], "y": [-0.24, -0.10]}},
                # 平放的"允许长轴朝向"（不写就用 SPAWN_LYING_YAWS 的实测表）
                # "lying_yaws": [215.0]},
    "basket":  {"x": [0.14, 0.28], "y": [0.02, 0.20]},
},
"target_object": "basket",
# 目标也被随机安放 → 判分取"篮子当前实际中心"，而不是写死的 0.22/0.10
"success": {"xy": [0.22, 0.10], "xy_ref": "target", ...},
```

**平放的朝向是"随机抽 + 生成前适配"**（用户要求："朝向也可以随机，不要固定 45° 角，
加之前可以调整角度适配"）：

* `pick_spawn_pose` 先在整个圆周上**均匀随机**取一个长轴朝向 θ；
* 再用 `adapt_lying_yaw` 把它**折到最近的一个实测能过关的角度**（`SPAWN_LYING_YAWS`
  = 45°/140°/215°/320° 四个斜对角族，见下面 ④ 的扫描表）—— 这就是"生成前调整角度适配"；
* 姿态四元数由 `lying_quat(θ)` 给出（绕局部 Y 躺下 + 绕世界 Z 转 θ），`placed_pose` 按
  旋转后的 AABB 重算"侧面贴桌"的 z，占地半径也按这个姿态算（33.6 → 73mm）。

* `libero_tasks.sample_spawn()` 在每个矩形里均匀抽 XY，再用**外接圆 + 25mm 间隙**做拒绝采样，
  避开其它物体的占地（`spawn_region` 里有多个物体时**按书写顺序**依次抽，后面的避让前面
  **已经抽到的实际位置** —— 否则两个随机物会按标称位置互相避让、实际却可能叠在一起），
  并且距桌沿至少 60mm；抽不到就退回标称位置（不抛异常）；
* **先抽姿态、再按该姿态的占地半径抽位置**：平放的瓶子占地外接圆从 33.6mm 涨到 73mm，
  不按姿态算就会和篮子叠在一起（`posed_boxes` + `footprint_radius_boxes`）；
* 位置只改 XY（z 由姿态重算），姿态默认**不动**（沿用 XML 的立姿）—— 只有区域里写了
  `poses` 才会随机（t1：立着 / 平放各半）；**没写 `poses` 的任务连代码路径都不进**，
  摆位与改动前一个字节都不差；
* 平放时 z 必须重算（`placed_pose`）：立着是瓶底贴桌，平放是**侧面**贴桌，
  沿用立姿的 z 会让瓶子悬空或穿桌；
* 写进物体的**自由关节**（`SimSession._apply_spawn`，对 `spawn_region` 里每个名字都生效），
  **不重写场景 XML** —— `build_all_scenes` / `render_preview` 产出的图仍固定可比；
* 夹爪闭合方向**跟着本局姿态走**（`SimSession._grasp_yaw`）：不再用"世界 AABB 谁短"猜
  （斜躺时 AABB 退化成 129×129mm 的近似正方形，猜错就横着扎进瓶身），改成把物体的
  **三条局部轴**转到世界系、只在**大致水平**的轴里挑**最短**的一条闭合
  （立着的瓶子/黄油→局部 Y；平放的瓶子→仍是局部 Y；平放的**黄油**→局部 Y 被转成竖直，
  退而选次短的局部 Z＝39.5mm 那对侧面）。技能库里同样按解析轴算
  （`grasp_axes_world` / `width_along_dir` / `long_axis_dir` / `thin_axis_world`），立姿时结果与旧算法逐字一致；
* 目标被随机化时，`check_success` 用 `xy_ref="target"` 取**目标物当前实际中心**判分
  （`place_object` 本来就是对准目标当前位置的，两边口径一致），判分文案会标注
  "（目标=basket当前位置）"；
* 这种任务**不再画固定目标圆盘**（`build_task_scene`）：那个圈只会停在 XML 里的标称位置，
  跟实际随机的篮子对不上，反而误导操作者 —— 篮子本身就是最好的目标标记。

**什么时候抽**：建会话时抽一次；界面上的「复位」= **重新抽一次**（换一局新摆位，瓶子和篮子一起换），
状态栏与素材分析栏会显示本局位置。基准脚本用 `SimSession(..., spawn_seed=...)` 固定种子
（种子取自它自己的 `rng`），所以同一版本重跑能复现同一串摆位。

#### 8.9.1 t2（黄油 → 盘子）照同一套做

```python
"spawn_region": {
    "butter": {"x": [0.00, 0.09], "y": [-0.21, -0.12],
               "poses": ["upright", "lying"],          # 立着 / 平放各 50%
               "lie_axis": "x",                        # 绕**长轴**躺（大平面朝下）
               "lying_yaws": [0.0, 135.0, 180.0, 315.0],   # 平放：实测夹得住的朝向
               "upright_yaws": None,                   # 立着：整圆周任意朝向
               "pose_regions": {"lying": {"x": [0.04, 0.09], "y": [-0.21, -0.12]}}},
    "plate":  {"x": [0.14, 0.24], "y": [0.02, 0.16]},
},
"success": {"xy": [0.20, 0.08], "xy_ref": "target", ...},   # 判分取盘子当前实际中心
```

与 t1 的差别（每条都是实测结论）：

| | t1 的瓶子 | t2 的黄油 |
| --- | --- | --- |
| 姿态 | "平放" = 绕**薄轴（局部 Y）**躺，薄边仍水平才夹得住 | "平放" = 绕**长轴（局部 X）**躺 → 厚边(17.4mm)朝上、76×39 的大平面贴桌（`lie_axis="x"`） |
| 立姿朝向 | 固定（XML 的 yaw） | **整圆周随机**（`upright_yaws: None`）：实测 8 个 yaw × 2 个位置 **16/16 都夹得住**（立着夹的是 17.4mm 薄边、爪口 50mm，IK 偏角不影响） |
| 收窄朝向的原因 | 瓶子 145.6mm 比篮子内腔 122×111mm 长，**落不进容器**（θ≈75~105°/255~285° 必卡沿口） | 落哪儿都行（盘面 137mm），但平放时能夹的只有 **39.5mm** 那对侧面、爪口 50mm —— **闭合轴要准到 ~8°** 才套得进去 |
| 允许的朝向 | θ ∈ {45°,140°,215°,320°}（斜对角族，9 个落点全过） | 平放 θ ∈ {0°,135°,180°,315°}（2 个位置全夹住；其余 4 个残余偏角 31°+，投影宽 72mm > 爪口，夹空） |
| 位置区域 | 收紧到"离底座 ≤ ~420mm、x ≤ 0.08"（躺姿要压到 810~830mm） | **整体**收紧（x≤0.09、y≥−0.21）+ 平放再收 x≥0.04（x≈0 那列夹得住但搬运会滑落）；盘子收到 x≤0.24/y≤0.16（避免"两个远角"那种 ~300mm 长距离搬运） |

为什么平放的朝向要筛：`calibrated_yaw` 只能在相隔 90° 的 4 个候选里挑，残余最多 45°；
而平放的黄油闭合轴必须与 39.5mm 那对侧面平行 —— 偏 31.5° 时沿轴投影宽
39.5·cos31.5 + 76.2·sin31.5 = **72mm** > 爪口 50mm，手指从黄油两侧滑过去、合爪到 0mm（夹空）。
实测 8 个朝向里 `yaw≈−90°/−135°` 那 4 个（即 θ=0/135/180/315）IK 咬得住，其余夹空
（试过"带符号闭环微调"修偏角，但 IK 的偏航误差随姿态换分支、方向关系不稳定，反而把能过的
朝向带坏，故放弃，改成按实测筛朝向）。

另外两项 t2 专属的调整（都是为了"夹得住、搬得稳"，不影响其它任务）：

* `GRASP_BAND_LADDER_TASKS["t2_butter_onto_plate"] = (0.000, 0.020, …)`：**dz=0 提到第一档**。
  黄油只有 17~40mm 厚，而指面全在 TCP 之上 ~73mm —— dz=+20 时指面整段停在黄油顶面之上、
  只咬住顶角（浅握），抬起 25mm 的校验能过，但**搬运途中会滑落**（整局失败：判分水平偏
  292mm、黄油躺在桌面上）。dz=0 时指面盖住黄油 32mm（807~839mm 对 800~839.5mm）。
* 平放件松手前"拿被夹物中心对准盘子中心"（§8.9 的 `align_xy(..., ref=...)`）同样适用。

**区域不是拍脑袋定的**（实测过程）：

| 步骤 | 工具 | 结果 |

**姿态随机（"平放"）是逐项筛出来的，不是随便给个朝向**（脚本：`_tools\diag_t1_pose*.py`、
`diag_t1_lying_*.py`）：

| 步骤 | 量到什么 | 结论 |
| --- | --- | --- |
| ① 篮子内腔 | 内腔只有 **122×111mm**（壁厚 13.3mm、内底 21.6mm），而瓶子长 **145.6mm** | 长轴与篮子边平行时正中心松手必**卡在沿口**（真实最低点 896~913mm）→ 平放必须**斜躺** |
| ② 躺姿要压到多低 | 躺姿抓取点 = 瓶底 +10mm ≈ **810~830mm**；实测机械臂在**离底座 ≥400mm** 时 TCP 压不到 870mm 以下（xy 还漂 5~20mm）、≤360mm 时能压到 815mm | 平放的**位置必须单独收紧**（`pose_regions`：x ≤ 0.08，离底座 291~400mm） |
| ③ 能夹 vs 够不着 | 平行夹爪沿一条**直线**闭合 → yaw 与 yaw±180° 物理等价（只是手指对调）；但躺姿只有**负角**那半圈够得着（−45°/−135° 各 6/6，+45° 2/6、+135° 1/6） | 躺姿的闭合角一律折算到 `(−180°, 0°]`（`reachable_yaw`）；立姿不折算 |
| ④ 朝向要随机 → 先量"哪些角度能进" | `diag_t1_yaw_sweep.py`：按长轴 θ 摆到篮子中心正上方、瓶底悬在篮口上方 15mm 凌空松手，每角度测 **9 个落点**（中心 + 8 向 15mm 偏移） | θ≈**45/140/215/320**（四个斜对角族）8~9/9 ✓；θ≈75~105°/255~285°（几乎与篮子边平行）**0~2/9** ✗；其余 2~8/9 ✗ → 这就是 `SPAWN_LYING_YAWS` |
| ⑤ 松手高度 | 同一套扫描换 15/60/150/300mm 四种高度 | **15mm 最好（四个斜对角合计 35/36）**；抬高反而更容易弹/架（300mm 时 30/36）→ `CONTAINER_DROP_CLEAR` 保持 15mm |
| ⑥ 松手前对准 | 平放的瓶子判分偏差只有 5~16mm 却架在沿口 → 根因是"**被夹物中心**没对准篮子中心"（物体相对 TCP 会偏十几毫米） | `place_object` 给平放物加一次**拿被夹物中心**做的 xy 闭环对准（`align_xy(..., ref=...)`） |
| ⑦ 判据 | 斜放物体的 **AABB 底面是空的**（806mm），真实最低点是 821mm | `check_success` 的高度改用**碰撞盒角点的最低点**（`object_lowest_z`）—— 轴对齐时与旧值完全相同，其余 8 关不受影响 |
| ⑧ 回归 | `diag_t1_pose_flow.py 12 laid_45,laid_140,laid_215,laid_320`；`bench_tasks.py 1 24`；`--all 1 --strict`；GUI 冒烟 | 平放端到端 **41/48（85%）**（各朝向 11/12、10/12、11/12、9/12）；t1 混合 **22/24**；**9/9**（其它 8 关帧数不变）；**30/30** |

> **平放不是 100%**：瓶子比篮子内腔还长，只能"斜着倒进去"，落定结果是**有随机性的**
> （实测 85%；失败几乎都是重心差几毫米 → 架在沿口）。立着那半边仍是 100%。
> 想要更稳可以把 `poses` 写成加权列表（如 `["upright","upright","upright","lying"]`
> = 25% 平放），或把 `lying_yaws` 收窄到某一个角度 —— 两者都只改 t1 的配置。

> 平放的两处"必须收紧"（斜 45° + 位置靠近底座）都是**机械臂物理限制**，不是调参能绕过的：
> 躺姿的夹取点比立姿低 ~90mm，而这条臂在远端压不到 870mm 以下；瓶子 145.6mm 又比篮子内腔
> 的对角线（164mm）只短 18mm，所以只能斜着滑进去。

> 篮子区域为什么是 x∈[0.14,0.28]、y∈[0.02,0.20]：离底座 0.41~0.59m，落在
> `set_ee_target` 的舒适半径 0.62m 内（再远末端目标会被拉回来，放置就不准了）；
> 下沿 x ≥ 0.14 是为了跟抓取物区域保持"33.6 + 115.6 + 25 ≈ 174mm"的占地间隙
> （番茄酱和篮子的外接圆半径），上沿 y ≤ 0.20 是实测里判分偏差还留 20% 余量的位置。
>
> 为什么只收缩/挑选区域、不去改抓取技能：那个失败点是"离底座近 + 偏 +y"特有的，
> 要修就得动**共享**的 `grasp_object`，会牵连其它 8 关。本轮按用户要求只动 t1，
> 所以用"区域避开"解决；以后给别的任务加随机化，照 ①②③ 重新量一遍再定矩形。

### 8.10 t1 夹得更深一点（`GRASP_BAND_LADDER_TASKS`）

用户报："夹子夹的不够深，夹得不够稳"。

量出来的原因（`_tools\diag_t1_depth.py`、`diag_t1_quality.py`）：**夹爪指面只有 74mm 长，
而且整段都在 TCP 之上**（指面 z ≈ TCP+0 ~ +73mm），而 ketchup 的 `grasp_tcp_offset=+39.8mm`
把 TCP 定在 912.8mm（瓶子 803~962mm）—— 于是指面只"咬"住瓶子**顶部 21~25mm**（只剩一点瓶颈），
低于此的部分全靠摩擦，搬运中瓶子会在爪内转/滑。

做法：给 t1 单独覆盖抓取档位（`GRASP_BAND_LADDER_TASKS`，只影响这一关）：

```python
"t1_ketchup_into_basket": (0.010, 0.020, 0.000, 0.045, 0.075),   # 第一档比原来低 10mm
```

逐档实测（完整任务，两个极端摆位；"合爪质量"= 开口−物体宽 / 两指接触点数）：

| dz | 指面盖住瓶子 | 抓取时 TCP | 合爪质量 | 结论 |
| --- | --- | --- | --- | --- |
| +20mm（原档） | 21~25mm | 932.5mm | +1.3mm / 1+1 指 | 稳但太浅 |
| **+10mm（新档）** | **31~36mm** | **922.5mm** | **+2.9~3.1mm / 两指都接触** | ✅ 更深且质量不掉 |
| 0mm | 41~45mm | 915.9mm | +8.9mm / 只有 1 指 ✗ | 远端"虚夹" |
| -20mm | 60mm | 897.4mm | 近处 3+2 指 ✓，远端 +7.1mm ✗ | 近处很好、远端没准头 |
| -35mm | 62mm | 892.9mm | 下探时把瓶子带歪（实时宽 37.5→67.9mm） | 远端会碰倒 |

**为什么不能再深**（`diag_t1_align.py`）：对齐结束时 TCP 与物体中心的 xy 误差在所有摆位都只有
0.9~1.8mm，但**低位姿态下位置伺服还有 6~9mm 静态漂移**（0.4~0.5m 处更明显），而爪口对 37mm 瓶子的
单边间隙只有 ~5mm —— 走得越深，手指越容易蹭到瓶身（实测远端"开口−物体宽"从 +1.3mm 恶化到 +11.9mm，
甚至把瓶子顶歪）。这是本机械臂在远端的物理限制，不是调参能绕过的。

效果（A/B 全流程实测，6 个摆位）：夹持高度**下移 ~10mm**、指面覆盖 **+45%**（25→35mm）、
搬运中瓶子相对夹爪的漂移在 5/6 个摆位上变小（最大从 54mm 降到 36mm）、爪内转动同样在 5/6 个摆位上变小；
`bench_tasks.py 1 12` **12/12**、区域网格 20/20、角点专项 7/7 全部通过。
